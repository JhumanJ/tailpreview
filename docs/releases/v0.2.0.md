# Tailpreview v0.2.0

Tailpreview now treats preview creation as a verified safe handoff rather than
returning the first reachable HTTPS URL.

## Safe handoffs

- Declare public verification paths in `.tailpreview.yml` with `verify`, or use
  repeatable `--verify PATH=MIN-MAX` flags.
- Same-origin redirects are followed for at most five hops.
- Redirects to loopback, another origin, downgraded HTTP, or credentialed URLs
  fail the handoff and trigger rollback.
- A `403` returns structured diagnostics that cover both development-server
  hostname rejection and application authorization.
- Verification targets and errors never retain query strings, fragments, or
  redirect paths.

## Agent contract

Successful `up` responses now include `preview.handoff_url`, declared
verification checks, and `last_verified_at`. Agents should return exactly this
handoff URL instead of reconstructing one or exposing a localhost upstream.

The new command revalidates an existing preview before it is reused:

```bash
tailpreview check <name> --json --non-interactive
```

`check` confirms local health, current MagicDNS identity, the exact Tailscale
Serve listener, absence of Funnel on that port, and every declared public
path. The bundled Codex skill has been updated to use this workflow.

Existing configurations remain valid and default to verifying `/`. The JSON
`url` field remains available for compatibility.
